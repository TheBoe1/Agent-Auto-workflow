# Tests · 回归用例集

> 本目录固化 mcn-agent-studio 的**路由与行为回归用例**，防止后续改动把已修好的问题重新引入。
> 来源：2026-09-01 隔离实测《V0.4 路由实测报告》（存于 skill 仓外的设计工作区）+ 阶段 1–5 各轮复测的 DoD。

## 测试方法（所有用例统一）

**起一个独立子代理，只读它"激活后应当可见"的最小文件集，模拟激活后的决策。** 子代理被允许读取入口指向的下游文件，并记录实际加载路径。禁止真的生产内容、建团队、跑完整流水线。

```
起子代理（无上下文）
   ↓ 只读 SKILL.md（+ 入口指向的下游文件）
   ↓ 喂入用例输入
   ↓ 观察：分类 / 加载 / 调用 / 是否追问
   ↓ 与「通过标准」逐条比对
```

## 可信边界（**必读，避免误判**）

这是**隔离环境下的模拟实测，不是平台真实触发**。

| 能证明 | 不能证明 |
|---|---|
| 模型读完入口文件后的路由判断倾向 | 平台真实触发时的行为 |
| 入口指令是否被遵守、是否存在矛盾 | 6 Agent 团队协作的真实表现 |
| 哪些资源会被加载 / 哪些是死资源 | 最终内容产出质量 |
| 是否具备需求澄清、任务分级机制 | Cron 与长跑场景的稳定性 |

## 新增用例规则

1. 每个用例必须写清**输入、通过标准、实测记录、结论**四段。
2. 通过标准必须是**可判定的行为**（如"未调用 X 工具"），不能是主观评价（如"效果好"）。
3. 用例失败时，记录是**文档缺失**（无依据可依）还是**文档矛盾**（有依据但冲突）——两者的修法不同。
4. 用例固化后，若行为有意变更，须同步更新用例与通过标准，不得留失效用例。
