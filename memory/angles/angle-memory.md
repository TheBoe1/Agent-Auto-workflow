# 角度记忆 · Angle Memory

> **比 content-history 更关键。** content-history 防「同一篇重发」，angle-memory 防「主题没变但角度反复用」。

## 为什么
主题「程序员学 AI」可以有无数篇，但只要角度一直在用 {效率提升, 被替代焦虑, 工具推荐, 学习路线}，
系统就该去搜：**未使用角度 / 用户痛点 / 市场空白**。

真正该检测的是：**内容 + 主题 + 角度**，而不是只检测标题。

## content_fingerprint（内容身份指纹，V0.4 升级）

> 查重不能只看 `similarity` 一个标量。两篇内容 similarity 都是 0.62，但一篇讲「临终细节」、一篇讲「成分科普」，本质完全不同。必须用**七维指纹**描述内容身份，大幅提升「不重复」的稳定性。

```yaml
content_fingerprint:
  topic: 主题        # 例：医疗人文 / 抗老护肤
  angle: 角度        # 例：临终细节 / 成分科普
  narrative: 叙事视角 # 第一人称观察 / 第三人称科普 / 对话体
  story: 故事ID      # ST-00X 或 无
  hook: Hook 类型    # 悬念 / 数据 / 冲突 / 共鸣
  structure: 结构模板 # 痛点→经历→方法→行动→互动
  expression: 表达基调 # 克制 / 幽默 / 专业背书
```

- **七维全同** → 直接拒绝（等同 `similarity >= 0.90`）。
- `topic`+`angle`+`narrative` 同，但 `hook`/`structure`/`expression` 可调 → 重构（换可调动维度或叠加新切口）。
- `topic` 同但 `angle` 不同 → 通过（但须记本表，累计使用次数）。

## 决策规则
1. 新内容选题时，team-lead 先读本表，列出该主题**已用角度**与已登记 `content_fingerprint`。
2. 优先选择「未使用角度」或「市场空白角度」。
3. 已用角度若必须用，需叠加新切口（新人群 / 新场景 / 新数据），不得原样复用。
4. 产出 `content_fingerprint` 后，与历史指纹比对：七维全同 → 拒绝；部分可调 → 重构；否则通过。
5. 每条新内容发布后，其 `content_fingerprint` 记入本表对应角度条目，作为后续冲突检查基线。
