# 互动机制记忆 · Engagement Patterns

> 与 `viral-patterns.md` 的分工：**Viral Pattern 决定"内容怎么展开"（正文骨架），Engagement Pattern 决定"读者为什么回应"（互动触发）。**

## 三层正交（不要混）

| 层 | 回答什么 | 例子 | 存哪 |
|---|---|---|---|
| Angle | 从哪儿切入 | 「人间真实」 | `../angles/angle-memory.md` |
| Viral Pattern | 内容怎么展开 | 「结果前置 → 补背景 → 留悬问」 | `./viral-patterns.md` |
| **Engagement Pattern** | **读者为什么回应** | **「在结尾抛一个两难选择题」** | **本文件** |

> 同一篇内容：用 PAT-01（结果前置）做骨架，用 ENG-02（两难选择）做结尾钩子，角度是「人间真实」。
> 三条轴独立组合，这才是防重复真正的空间。

## 为什么需要单独存

缪生花的产出规范里只有一句「1 条互动提问（引导评论区互动）」——**没有机制库，每次都是临时编一句**。
临时编的互动提问三大通病：老套（"你怎么看？"）、无争议（无人回）、与内容脱节（像硬贴上去的）。

Engagement Pattern 层的作用：把"结尾互动"从随机发挥变成**可选机制 + 可复用 + 可回测**。

## 互动类型与对应指标

选 Pattern 前先明确**这一篇要哪个指标**——不同机制驱动的平台行为不同：

| 目标指标 | 说明 | 优先机制类型 |
|---|---|---|
| 评论量 | 读者愿意开口 | 提问型 / 争议型 / 求助型 |
| 收藏量 | 读者觉得"以后有用" | 清单型 / 干货型 / 模板型 |
| 转发量 | 读者觉得"得让别人看到" | 共鸣型 / 立场型 |
| 涨粉 | 读者觉得"这个号值得跟" | 系列型 / 承诺型 |

## 机制登记表

状态列：`优先未用`（0 次）/ `可用`（低频）/ `高频慎用`（≥3 次，需冷却）

| ENG-ID | 机制名 | 触发方式 | 驱动指标 | 适用 | 不适用 | 使用次数 | 状态 |
|---|---|---|---|---|---|---|---|
| ENG-01 | **两难选择** | 结尾抛 A/B 两难，逼读者站队 | 评论 | 有争议空间的议题 | 非黑即白的医疗建议（易误导） | 0 | 优先未用 |
| ENG-02 | **经历征集** | "你遇到过吗？评论区说说" | 评论 | 普适经历、共鸣强的话题 | 隐私敏感、病患身份话题 | 0 | 优先未用 |
| ENG-03 | **干货承诺** | "完整清单我整理好了，先收藏" | 收藏 | 攻略、清单、资源类 | 叙事故事（无干货可藏） | 0 | 优先未用 |
| ENG-04 | **立场共鸣** | 替读者说出他想说不敢说的话 | 转发 | 情绪浓度高、有共同处境 | 中立科普、客观陈述 | 0 | 优先未用 |
| ENG-05 | **未完成悬问** | 结尾留一个真问题，作者也不给答案 | 评论 | 开放议题、无标准答案 | 需要明确结论的医疗科普 | 0 | 优先未用 |
| ENG-06 | **纠错邀请** | "我可能说得不全，专业朋友来补" | 评论 | 专业垂类、医生/从业者受众 | 泛人群娱乐内容 | 0 | 优先未用 |
| ENG-07 | **系列预告** | "下篇讲 XX，想看的扣 1" | 涨粉 + 评论 | 可拆分成系列的主题 | 一次性话题 | 0 | 优先未用 |
| ENG-08 | **数据投票** | "选 A 还是 B？我猜多数人选错" | 评论 | 有认知落差的知识点 | 无对错之分的主观偏好 | 0 | 优先未用 |

## 选择规则

1. **先定目标指标**：这一篇要评论还是要收藏？按「互动类型与对应指标」表选机制类型。
2. **再查防重复**：读本表使用次数，优先选 0 次或低频的 ENG-ID；同一机制连续使用 ≥3 次必须换。
3. **与 Viral Pattern 搭配**：结果前置（PAT-01）天然配未完成悬问（ENG-05）；清单模块（PAT-05）天然配干货承诺（ENG-03）。错配会显得割裂。
4. **与内容一致**：互动钩子必须从内容里长出来，禁止硬贴。"你怎么看？"这类无信息量的提问不得当作 Engagement Pattern。
5. **发布回填**：发布数据回来后，team-lead 在 Phase 7 更新本表使用次数与表现（哪个机制真的带来了评论）。

## 与 performance-memory 的闭环

```
选 ENG-ID → 落 04_copy.md → 发布 → 回测互动数据
   ↑                                      ↓
   └────── team-lead Phase 7 更新本表 ←────┘
```

- 表现好的机制 → 状态标 `高效`，可提升复用优先级。
- 表现差的机制 → 状态标 `低效`，即便低频也不再优先。
- **只有带回测数据的机制才值得复用**；无数据的机制一律按 `优先未用` 处理，不得宣称"有效"。

## 医疗垂类特别约束

- **ENG-02（经历征集）在病患话题慎用**：公开征集病情经历可能诱导用户披露隐私，且评论区易出现未经核实的医疗建议。
- **ENG-01（两难选择）、ENG-05（未完成悬问）在医疗科普中禁用**：医疗结论不应被包装成"无标准答案"，避免读者据此自行判断。
- 互动引导不得诱导用户做医疗决策，不得出现"你也试试""建议自查"类表述。

## 写入协议

与其他记忆类一致：**Agent 只读，team-lead 在 Phase 7 统一 promote**（APPEND / MERGE / UPDATE / REJECT，禁止覆盖历史）。新机制的引入须附 evidence（来源 + confidence + 回测数据），不得凭感觉新增。
