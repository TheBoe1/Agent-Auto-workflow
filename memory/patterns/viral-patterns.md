# 爆款机制记忆 · Viral Patterns

> **Pattern（机制）≠ Angle（角度）。** 这两件事必须分开存、分开用，混在一起就是重复生产的源头。

## Angle ≠ Pattern（本文件存在的原因）

| | Angle（角度） | Pattern（机制） |
|---|---|---|
| 回答什么 | **从哪儿切入** | **怎么展开** |
| 例子 | 「人间真实」「成分科普」「医者仁心」 | 「先给结果 → 再补背景 → 最后留一个没有答案的问题」 |
| 层级 | 主题下的切入视角 | 跨主题可复用的结构打法 |
| 存哪 | `../angles/angle-memory.md` | **本文件** |
| 影响指纹 | `content_fingerprint.angle` | `content_fingerprint.structure` |

**两者正交**：同一个角度可以用不同机制表达，同一个机制可以承载不同角度。

> 「人间真实」是角度。
> 「先给结果，再补背景，最后留下一个没有答案的问题」是内容机制。
> 这两件事不能混为一谈——角度用尽了可以换机制，机制用老了可以换角度，**两条轴都能走，才不容易撞车**。

## 为什么需要单独存 Pattern

缪生花的默认正文模板原本是硬编码的「痛点 → 经历 → 方法论 → 行动建议 → 互动提问」。
**所有内容套同一个骨架，本身就是一种重复**——即使角度没重复，读者也会觉得"怎么每篇都这个味儿"。

Pattern 层的作用：把单模板扩展成**可选的结构机制库**，让缪生花依据内容类型选机制，而不是无脑套模板。

## 与 content_fingerprint 的关系（关键）

`content_fingerprint` 七维中的 `structure`（结构模板）维度，**取值来自本文件的 PAT-ID**。

```
选 Pattern → 写入 content_fingerprint.structure → 参与七维指纹比对
```

- 七维全同（含 structure 相同）→ 直接拒绝。
- `topic`+`angle`+`narrative` 同，但换一个未用过的 PAT-ID → **构成有效重构**（换 structure 是可调动维度）。
- 因此：**换 Pattern 是撞车后最低成本的重构手段**，优先于换角度。

## 机制登记表

状态列：`优先未用`（0 次）/ `可用`（低频）/ `高频慎用`（≥3 次，需冷却）

| PAT-ID | 机制名 | 结构骨架 | 为什么有效 | 适用 | 不适用 | 使用次数 | 状态 |
|---|---|---|---|---|---|---|---|
| PAT-01 | **结果前置** | 先抛结果/结论 → 补背景 → 最后留一个没有答案的问题 | 结果反差制造好奇缺口；结尾开放问题直接驱动评论 | 经验复盘、数据类、亲历故事 | 需要情感铺垫的沉重题材 | 0 | 优先未用 |
| PAT-02 | **痛点共鸣** | 痛点场景 → 亲历经历 → 方法论 → 行动建议 → 互动提问 | 痛点前置建立"说的就是我"的代入感 | 科普、教程、经验分享 | 无明确痛点的话题 | 0 | 优先未用（原默认模板） |
| PAT-03 | **反常识开场** | 反直觉断言 → 论证过程 → 认知反转 → 新结论 | 打破预期，制造"必须看完"的张力 | 辟谣、认知纠偏、专业科普 | 严肃医疗建议（易误导） | 0 | 优先未用 |
| PAT-04 | **对比式** | Before（状态 A）→ 转折事件 → After（状态 B）→ 归因 | 落差直观，易被截图传播 | 变化/成长/效果类 | 涉及疗效对比（医疗合规高风险） | 0 | 优先未用 |
| PAT-05 | **清单模块** | 总述 → N 个并列要点（小标题化）→ 收尾总结 | 降低阅读成本，易收藏 | 攻略、清单、资源汇总 | 叙事性故事（会被拆碎） | 0 | 优先未用 |
| PAT-06 | **悬念递进** | 悬念开场 → 层层递进揭信息 → 高潮 → 留白 | 好奇心驱动完读 | 故事、案例、事件复盘 | 干货速查类 | 0 | 优先未用 |
| PAT-07 | **时间线叙事** | 时间锚点 → 按节点推进 → 关键转折 → 现状 | 真实感强，天然带证据链 | 亲历、病程、成长记录 | 无时间跨度的观点文 | 0 | 优先未用 |
| PAT-08 | **对话体** | 一段真实对话开场 → 引出议题 → 展开 → 收尾 | 口语现场感，去 AI 味效果最强 | 医患对话、咨询场景 | 需严谨论证的科普 | 0 | 优先未用 |

## 选择规则（缪生花 / 主理人）

1. **先看内容类型**：故事类优先 PAT-06/07，科普类优先 PAT-02/03，干货类优先 PAT-05，经验类优先 PAT-01。
2. **再查防重复**：读本表使用次数，**优先选 0 次或低频的 PAT-ID**；同一 PAT-ID 连续使用 ≥3 次须换。
3. **撞车重构时**：优先换 Pattern（改 `structure`），其次才换角度（改 `angle`）——换机制成本更低。
4. **写入指纹**：选定后把 PAT-ID 写进 `content_fingerprint.structure`，参与七维比对。
5. **发布回填**：发布数据回来后，team-lead 在 Phase 7 更新本表使用次数与表现。

## 医疗垂类特别约束

- **PAT-03（反常识开场）、PAT-04（对比式）在医疗内容中慎用**：反直觉断言与疗效对比极易触发平台医疗合规风险，且可能构成误导。确需使用时，结论必须来自 A/B 级可核实素材，且不得出现"治愈""根治"类表述。
- 医疗内容的 Pattern 选择须同时通过 `core/quality-gates.md` 的平台安全门禁。

## 写入协议

与其他记忆类一致：**Agent 只读，team-lead 在 Phase 7 统一 promote**（APPEND / MERGE / UPDATE / REJECT，禁止覆盖历史）。新 Pattern 的引入须附 evidence（来源 + confidence），不得凭感觉新增机制。
