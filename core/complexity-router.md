# 复杂度路由（Complexity Router）

任务分类确定"做什么"（见 `task-router/task-types.md`），复杂度确定"做到什么程度"。两级判断共同决定加载哪些资源（见 `context-loader.md`）。

## 四级复杂度

| 级别 | 名称 | 含义 | 典型请求 | 资源规模 |
|---|---|---|---|---|
| L0 | Direct | 已有完整内容，简单处理 | "把这段改得口语一点" | 单工具直调 |
| L1 | Assisted | 需要少量工具辅助 | "分析这篇有没有 AI 味" | 单工具 + 工具索引 |
| L2 | Research | 需要外部信息 | "研究一下最近一人公司有什么热门方向" | 检索链 + 分析 |
| L3 | Full Pipeline | 完整内容生产 | "每天帮我找一个适合账号的选题并做成图文" | 完整团队 + 流水线 |

## 判定规则

1. **先看产出物**：任务分类已判定是否产出内容——
   - 不产出（RESEARCH / ANALYSIS / REVIEW / HUMANIZE / GROWTH 单点）→ 默认 L0-L2，按是否需要外部信息细分
   - 产出（PRODUCTION / RECONSTRUCTION）→ 默认 L3；单篇快速生产且素材齐备可降 L2
2. **看外部信息需求**：需要检索 / 调研 → 至少 L2；只需处理已有文本 → L0/L1。
3. **看规模**：单篇单次 → L0-L2；系列 / 每日 / 批量 → L3。

## 与任务类型的关系

| 任务类型 | 默认复杂度 | 说明 |
|---|---|---|
| CONTENT_PRODUCTION | L3 | 完整流水线；单篇快速生产且素材齐备可降 L2 |
| CONTENT_RECONSTRUCTION | L2 | 查重 + 换角度重构 |
| CONTENT_RESEARCH | L2 | 需外部信息 |
| CONTENT_ANALYSIS | L2 | 分析外部内容；纯文本分析可降 L1 |
| CONTENT_REVIEW | L1 | 已有内容审核 |
| HUMANIZE_AUDIT | L0/L1 | 纯改写 L0，需查证事实 L1 |
| ACCOUNT_GROWTH | L2 | 需账号数据与市场信息 |

## 升级与降级

- 运行中发现比预判更复杂（如检索发现高重复需重构）→ 升级复杂度并重新规划上下文。
- 用户明确要求简化（"不用查了直接写"）→ 可降级，但必须显式标注降级与风险，不得伪装为完整模式。
