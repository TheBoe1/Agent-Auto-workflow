# 任务分类流程（Task Classifier）

将用户请求映射为 7 种任务类型之一（类型定义见 `task-types.md`，任务对象契约见 `task-schema.md`）。分类是系统第一步，必须在任何工具调用之前完成。

## 分类四步

### 第 1 步：判定是否"产出内容"

先看请求里有没有**产出意图**：

- 产出词：帮我做 / 写 / 出一篇、生成、重写、重构、做一版
- 非产出词：看看、分析、调研、拆解、审核、检查、改一下、规划、建议

产出意图 → 候选 `CONTENT_PRODUCTION` / `CONTENT_RECONSTRUCTION`
非产出 → 候选其余 5 种

### 第 2 步：按动作类型细分

| 动作信号 | 任务类型 |
|---|---|
| 生产（做/写/出）+ 主题 | CONTENT_PRODUCTION |
| 重构（换角度重写） | CONTENT_RECONSTRUCTION |
| 研究（调研/趋势/话题） | CONTENT_RESEARCH |
| 分析（拆解/爆款/别人怎么写） | CONTENT_ANALYSIS |
| 审核（能不能发/审稿） | CONTENT_REVIEW |
| 去 AI 味（改得像人） | HUMANIZE_AUDIT |
| 养号/涨粉/冷启动 | ACCOUNT_GROWTH |

### 第 3 步：意图混合处理

请求同时含"分析"和"生产"意图（如"先看看别人怎么写，再帮我写一篇"）：

- 归为 `CONTENT_PRODUCTION`，但执行时先走研究阶段（Phase 1 检索 + 分析），再进入生产。
- 不得跳过研究直接生产。

### 第 4 步：不确定时确认

两个以上类型特征同时出现且无法判断主意图，或用户请求过于模糊时，向用户确认任务意图。禁止猜测后直接开工。

## 关键规则（防误判）

1. **"只分析"≠"要产出"**：请求里没有产出词（做 / 写 / 出 / 生成）时，不得进入生产流程。
2. **轻量任务不建团**：除 `CONTENT_PRODUCTION` 外，其余类型均不建团队（见 SKILL.md 编排 SOP 任务分级）。
3. **生产必澄清**：`CONTENT_PRODUCTION` / `CONTENT_RECONSTRUCTION` 涉及产出时，先过需求澄清闸门（账号定位 / 目标受众 / 内容方向）。
4. **分类在前**：未完成分类，不得调用任何工具。
