# research-workflow 检索分析 skill

> 结构化研究方法论，引导 agent 完成多阶段研究并生成中间文件报告。
> 来源：jwynia/agent-skills · `skills/general/research/methodology/research-workflow`

## 适用场景

**用**：需要全面研究一个主题、多查询搜索、来源可信度与综合分析、输出研究报告、分析平台链接。
**不用**：单次快搜即可（改用 bb-browser 直接搜索）、简单事实查询、无需综合。

## 前置依赖

- **web search capability**（由 `tools/research/bb-browser.md` 提供）
- 清晰的研究问题或目标链接

## 四阶段工作流

```
1. PLANNING          2. EXECUTION          3. ANALYSIS           4. SYNTHESIS
┌────────────┐      ┌────────────┐       ┌────────────┐        ┌────────────┐
│ 定义研究问题│ ───▶ │ 执行多查询  │ ───▶  │ 分组找规律  │ ───▶   │ 综合成报告  │
│ 拆子问题   │      │ 评估来源    │       │ 共识/冲突/ │        │ 可执行输出  │
│ 规划检索   │      │ 记录每次搜索│       │ 空白/置信度│        │ 附来源引用  │
└────────────┘      └────────────┘       └────────────┘        └────────────┘
```

### Phase 1 · Planning（规划）
1. 把主题转成具体可回答的研究问题（2–4 个）。
2. 拆解子主题：核心概念 / 现状 / 收益 / 挑战 / 最新进展 / 趋势。
3. 规划检索策略：先宽泛（overview）→ 再具体（case study）→ 最后验证（criticism / latest）。

### Phase 2 · Execution（执行）
1. 按顺序执行查询（用 bb-browser）。
2. 记录每次搜索：查询词、结果数、关键发现（2–3 条）、值得注意的来源、新问题。
3. 评估来源可信度：作者/机构、出版方、日期、引用。
4. 迭代：发现空白补新查询，验证惊人结论。

### Phase 3 · Analysis（分析）
1. 按主题分组发现。
2. 找规律：**共识**（多来源一致）/ **冲突**（来源分歧）/ **空白**（未解答）/ **趋势**。
3. 标注置信度：高（多权威来源一致）/ 中（证据有限）/ 低（单一来源或矛盾）。
4. 记录局限：找不到的、需进一步研究的、潜在偏见。

### Phase 4 · Synthesis（综合）
1. 选输出格式：摘要 / 完整报告 / 行动项。
2. 写综合：重要发现前置、连接相关概念、标注置信度、承认局限、引用来源。
3. 可执行元素：关键要点（3–5 条）、建议、进一步研究方向、决策点。

## 中间文件（落盘）

```
runs/{run_id}/
├── research-plan.md        # Phase 1 产出：研究问题 + 检索计划
├── search-log.md           # Phase 2 产出：每次查询的记录 + 来源评估
├── findings.md             # Phase 3 产出：分组发现 + 共识/冲突/空白 + 置信度
└── research-report.md      # Phase 4 产出：综合报告 + 可执行元素
```

## 质量清单（交付前自检）

- [ ] 研究问题清晰
- [ ] 执行了 ≥3–5 个查询
- [ ] 来源评估了可信度
- [ ] 发现按主题分组
- [ ] 标注了共识与冲突
- [ ] 标注了置信度
- [ ] 承认了局限
- [ ] 输出可执行

## 与 MCN 专家团的衔接

- **闻风向**：用 research-workflow 做趋势与竞品研究，产出选题报告。
- **查无异**：用 research-workflow 做同主题多查询检索，产出查重报告（附来源）。
- 检索失败时如实标注，进入「风险确认节点」，禁止臆断。
