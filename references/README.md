# References · 复杂知识按需加载区

> **本目录的定位：SKILL.md 与 core/ 保持"流程与规则"，复杂领域知识、长尾细则、判定清单按需进这里。**
> 这是渐进式披露（Progressive Disclosure）的第三层——**入口只放导航，细节只在需要时才读**。

## 为什么需要这一层

SKILL.md 是模型激活后唯一可见的入口文件。如果把所有领域知识都堆进去，会挤爆上下文；
如果堆在 core/，规则层会被知识细节淹没。所以：

```
SKILL.md（入口导航）
   ↓ 需要判定时
core/（路由规则 + 门禁 + 状态机）
   ↓ 需要领域细节时
references/（本目录：长尾知识、清单、细则）
```

## 本目录 vs 其他目录（职责边界，禁止混放）

| 目录 | 存什么 | 不存什么 |
|---|---|---|
| `SKILL.md` | 入口导航、任务分类简表、复杂度简表、编排 SOP、铁律 | 领域知识全文、工具细节 |
| `core/` | **判定规则**：任务路由、复杂度、质量门禁、工具状态、上下文加载 | 领域知识、操作清单 |
| `tools/` | **工具契约**：Schema、配置、降级、License | 领域方法论 |
| `memory/` | **账号资产**：角度、故事、风格、表现、机制库 | 通用知识（与账号无关的） |
| **`references/`** | **领域知识与长尾细则**：判定清单、平台规则、合规细则、写作方法论 | 流程规则（回 `core/`）、工具契约（回 `tools/`） |

> 判定口诀：**流程问题查 `core/`，工具问题查 `tools/`，账号问题查 `memory/`，领域细节查 `references/`。**

## 新增规则

1. **有内容才建文件**：禁止为了"结构完整"建空目录或占位文件。
2. **必须在入口登记**：新文件写完必须同步登记到本表，并在 `../core/context-loader.md` 的加载表中加入触发条件。**未登记 = 死资源**（这是本项目已有教训：`registry/` 四件套曾因 SKILL.md 未引用而全部停摆）。
3. **单一主题**：一个文件只讲一个主题，避免变成大杂烩。
4. **可判定优先**：优先沉淀"能照着做检查"的清单型知识，而非泛泛而谈的方法论。
